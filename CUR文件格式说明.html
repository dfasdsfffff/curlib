CUR 文件格式说明

CUR 是 PSD-BPA/PSModel 使用的二进制曲线文件。文件由 16 字节文件头、曲线描述记录和小端序 float32 数据组成。曲线描述中的文本通常使用 GBK 编码，数值区不是文本。

本文描述当前解析库支持的两种布局：普通 CUR 和 FDS 生成的 CUR。曲线数量、采样点数量和数据偏移必须从文件头计算，不能写死为某个 IEEE 算例的固定值。

1. 文件头

文件头位于偏移 0，包含 4 个小端序 uint32：

偏移长度字段说明
04header0文件标识或版本相关字段。当前解析库保留原值，不解释业务含义。
44curveCountMinusOne实际曲线列数减一。
84sampleCount每条曲线的采样点数量。
124reserved保留字段。不同文件可能为不同值，当前解析库不使用。
 
curveCount  = curveCountMinusOne + 1
sampleCount = header.sampleCount

数据区包含 curveCount × sampleCount 个单精度浮点数。第 0 列通常是时间列，后续列是监视曲线。

2. 普通 CUR 布局

普通 CUR 在文件头后保存 curveCount - 1 条曲线描述记录，每条记录 100 字节。第 0 列通常没有描述记录，描述从第 1 列开始。

区域偏移或长度说明
文件头0，16 字节4 个 uint32。
曲线描述16，(curveCount - 1) × 100 字节对应第 1 到第 curveCount - 1 列。
数值区16 + (curveCount - 1) × 100按列连续排列的浮点数。
结束标记通常为文件最后的 0x1A不属于浮点数据。
 
dataOffset  = 16 + (curveCount - 1) * 100
valueOffset = dataOffset + (column * sampleCount + row) * 4

3. 普通 CUR 的曲线描述

第 i 条普通 CUR 描述记录对应第 i + 1 列：

recordOffset = 16 + i * 100
记录内偏移长度说明
080 字节设备、对象或附加标识，通常为 GBK 文本，尾部可能用空格填充。
8020 字节曲线名称，通常为 GBK 文本，尾部可能用空格填充。

文件读取后，解析库会为这两个字段添加 C 字符串结束符。原始有效长度最多分别为 80 和 20 字节。

4. FDS CUR 布局

FDS 生成的 CUR 在普通文件头后增加 3 条 100 字节元数据记录，然后保存 curveCount 条曲线头记录。解析库通过头部的 PowerFlow FileName 和 Executed Time 标记自动识别该布局。

区域偏移或长度说明
文件头0，16 字节与普通 CUR 相同。
FDS 元数据16，300 字节3 条额外记录，包含程序、文件名和执行时间等信息。
曲线头16 + 3 × 100，curveCount × 100 字节包含第 0 列在内的所有曲线头。
数值区16 + (curveCount + 3) × 100按列连续排列的浮点数。
 
fdsDataOffset = 16 + (curveCount + 3) * 100
valueOffset   = fdsDataOffset + (column * sampleCount + row) * 4

FDS 曲线头不是普通 CUR 的“80 字节设备字段 + 20 字节名称字段”布局。当前解析库将每条 FDS 曲线头的前 20 字节映射到 device_gbk，接下来的 20 字节映射到 name_gbk，其余头部内容保留在文件中但不暴露给 CurCurve。

已验证的 FDS 文件在结束标记前固定少 80 个数据字节，即少 20 个 float32 值。当前解析库为最后缺失的 20 个值补 0.0，并将最后的 0x1A 排除在数据区之外。

5. 数据区

数据区使用 IEEE-754 单精度浮点数，每个值 4 字节，小端序排列：

float32 little-endian

数据按列连续存储：

列 0：sampleCount 个值
列 1：sampleCount 个值
...
列 curveCount - 1：sampleCount 个值

给定数据区起点 dataOffset 后，第 column 列第 row 个值的字节偏移为：

valueOffset = dataOffset + (column * sampleCount + row) * 4

6. Python 读取示例

推荐使用绑定库读取。它会自动识别普通 CUR 和 FDS CUR，不需要调用方判断文件类型：

from python.cur import read, validate

path = r"IEEE30_FDS.cur"
library = r"build-fix\Debug\curlib.dll"

validate(path, library)
file = read(path, library)

print("曲线列数：", file.curve_count)
print("采样点数：", file.sample_count)
print("第一列前 5 个值：", file.curves[0].values[:5])
print("第一列名称：", file.curves[0].name)

7. C 接口中的内存和编码

typedef struct {
    char device_gbk[81];
    char name_gbk[21];
    float *values;
} CurCurve;

typedef struct {
    uint32_t header0;
    uint32_t curve_count;
    uint32_t sample_count;
    CurCurve *curves;
} CurFile;
  • device_gbk 和 name_gbk 保存原始 GBK 字节，不应按 UTF-8 直接解码。
  • values 指向 sample_count 个 float。
  • cur_read 成功后，调用方必须使用 cur_free 释放内存。
  • Python、Go、Rust、Java 和 C# 绑定会复制数据，再释放 C 层内存。

8. 写回和 SWX 导出

cur_write 始终写出普通 CUR 布局。读取 FDS 后再写回 CUR 时，数值会写入标准布局，FDS 的 3 条元数据记录和其他 FDS 专用头部信息不会保留。

cur_export_swx 输出的是按曲线列排列的平面文本，保留曲线顺序和名称字节。它不会重建 PSD-BPA 原始 SWX 的多段标题、分组和对齐空格。

9. 解析注意事项

  • 必须使用二进制模式读取文件。
  • 不要把数值区当作 GBK 文本读取。
  • 不要将数据解释为 double；格式使用 4 字节 float32。
  • 不要根据文件名中的 FDS 判断格式，应检查文件内容。
  • 不要把文件末尾的 0x1A 当作浮点数据。
  • 曲线数量和采样点数量由文件头决定，不同算例的数量可能不同。
